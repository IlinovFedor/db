В строке 94 инициализируется обработчик HTTP-файлового сервера, требуемого для раздачи файла стилей css.
Этот файл определяет только визуальное оформление сайта.
В его качестве была выбрана открытая библиотека стилей \texttt{pico.css} \cite{wiki:pico.css}

Обработчик --- функция, принимающая типы \texttt{http.ResponseWriter} (используется для записи в HTTP-соединение) и
\texttt{http.Request} (запрос клиента).

В следующей строке создается шаблон на основе файла \texttt{index.html} и проверяется корректность выполнения этой
функции.
В случае, если функция завершилось ошибкой, выводится соответствующее сообщение в консоль и программа завершает
выполнение
с кодом 1.

В строках 101--107 инициализируется пул соединений к СУБД, где указывается название хоста, порт подключения,
имя базы данных и пользователя, а так же пароль.
В строках 109--112 также проверяется наличие ошибки, по аналогии с предыдущим абзацем.

В строках 114--117 создается маршрутизатор (мультиплексор) HTTP-запросов:
\begin{enumerate}
    \item По пути \texttt{/} --- главная страница.
    Для обработки запросов используется функция \texttt{Root}, принимающая HTML-шаблон и возвращающая требуемый
    обработчик.
    Ключевым словом \texttt{GET} определяется допустимый HTTP-метод, а при помощи символов \texttt{\{\$\}} мы говорим
    программе, что все иные пути запрещены.
    В таком случае при попытке зайти на иной путь сервер вернет ошибку \texttt{404},
    а для всех остальных методов помимо \texttt{GET} клиенту возвращается HTTP-статус \texttt{405 Method Not Allowed}.
    \item По пути \texttt{/css/} должны находиться файлы стилей.
    Используется обработчик, созданный в строке 95.
    \item По пути \texttt{/query} --- результаты выполнения SQL запросов.
    Функция \texttt{Queries} принимает HTML-шаблон и созданный в строках 101--107 пул соединений.
\end{enumerate}

В строках 119--124 запускается HTTP-сервер, находящийся по адресу \texttt{httpAddress}.
Этот адрес задан как константа в начале программы и равен \texttt{localhost:8080}

Далее в ней выполняются следующие шаги:
\begin{enumerate}
    \item Получение идентификатора операции \texttt{opId} из Query HTTP-запроса;
    \item Формирование объекта структуры \texttt{Response} и переменной для ошибок \texttt{err};
    \item Выполнение функции \texttt{execQuery}, перезаписывающей переменные \texttt{resp} и \texttt{err} и принимающей
    пул запросов и сам SQL-запрос;
    \item Обработка ошибки, возникшей при выполнении функции \texttt{execQuery};
    \item Запись идентификатора операции в параметр \texttt{Type} переменной \texttt{resp};
    \item Сборка и отправка итогового HTML-документа, обработка ошибки.
\end{enumerate}

Структура HTTP-ответа (листинг \ref{lst:response}) содержит в себе следующие поля:

\begin{itemize}
    \item \texttt{Type} типа \texttt{string}.
    Хранит в себе идентификатор операции;
    \item \texttt{Rows} типа \texttt{any}.
    Хранит в себе сами SQL-ответы.
    Тип any обусловлен тем, что все три запроса имеют разную структуру ответа.
\end{itemize}

Функция \texttt{execQuery} (листинг \ref{lst:execQuery}) используется для выполнения SQL запросов.

\begin{listing}[H]
    \gofile[firstline=69, lastline=91, firstnumber=69]{../main.go}
    \caption{Вспомогательная функция execQuery}
    \label{lst:execQuery}

В качестве аргументов она принимает пул соединений СУБД и сам запрос.
Возвращает объект структуры \texttt{Response} и сообщение об ошибке.
В первых строках выполняется сам SQL запрос и обрабатывается ошибка.
В случае её возникновения функция завершается и возвращает полученную ошибку.

Далее создается массив \texttt{rows}, хранящий строки ответа.
В цикле \texttt{for} при помощи метода \texttt{exec.Next()} проверяется, остались ли ещё в ответе необработанные строки.
Каждая строка кодируется в массив значений при помощи \texttt{exec.Values()}, обрабатывается ошибка, и в случае успеха
значения записываются в массив \texttt{rows}.

Далее SQL-запрос завершается, формируется ответ, и происходит возврат из функции.
